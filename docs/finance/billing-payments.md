# 財務與結算｜發票 / 收付款頁企劃

## 一、頁面定位

發票 / 收付款頁的定位，是 CRM 中財務與結算模組的**單筆財務資料管理中心**。它不只是查看發票，也不只是記錄收款或付款，而是將發票、收款、付款、異動處理、關聯資料與狀態追蹤整合在一起的作業頁。

這頁的核心價值，是讓使用者可以清楚掌握：

* 這筆發票目前是否已開立、作廢、折讓、重開
* 這筆應收 / 應付款目前收了多少、付了多少
* 是否存在部分收付款、逾期、異常
* 它關聯哪個客戶、案件、營收、對帳資料
* 所有重要異動是否有留下原因、紀錄與附件

因此這頁不是單純表格頁，也不是單純報表頁，而是**財務單據與金流狀態的管理頁**。

## 二、頁面目的

本頁主要目的如下：

1. 管理發票資料
2. 管理收款與付款紀錄
3. 管理發票異動處理，例如作廢、折讓、退回重開
4. 追蹤收付款進度與逾期狀態
5. 建立與客戶、案件、營收、對帳資料的關聯
6. 提供異常追查與歷程查看能力
7. 作為單筆財務資料的主要操作入口

## 三、適用角色

本頁主要服務以下角色：

* 財務人員：處理發票、收付款、折讓、作廢、異常與附件
* 業務主管：查看案件財務狀態與收款進度
* 營運 / 管理者：掌握整體待開票、待收款、待付款與逾期狀況
* 一般業務：查看自己案件的發票與收款狀態

## 四、頁面結構判斷

這頁建議採用兩層結構：

### 1. 列表頁

用途是快速查看、篩選、搜尋與管理多筆資料。
重點在：

* 看狀態
* 找異常
* 找未完成項
* 進入單筆詳情

### 2. 獨立詳情頁

用途是承接單筆資料的完整閱讀與操作。
重點在：

* 查看完整資料
* 執行發票異動
* 管理收付款紀錄
* 查看附件與異動歷程
* 補充備註與原因

這頁不建議只用 Drawer，因為：

* 單筆欄位多
* 狀態多
* 會有多區塊資訊
* 有實際管理操作需求
* 很可能需要頁籤分區顯示

## 五、主 UIUX 建議

我建議主模組架構如下：

* 上方摘要卡
* 中上方篩選|主列表
* 點擊後進入獨立詳情頁

而列表頁內部資料視角，可以用 **Tabbar 切換**，建議分成：

* 發票
* 收款
* 付款

也就是：**同一模組、同一套路，但不同資料視角切換**。這樣比拆成三個完全獨立頁面更一致，也更符合你目前 CRM 企劃脈絡。

## 六、頁面資訊架構

### 6.1 列表頁結構

#### 頂部摘要區

建議顯示：

* 待開票筆數 / 金額
* 待收款筆數 / 金額
* 待付款筆數 / 金額
* 逾期未收款筆數 / 金額
* 逾期未付款筆數 / 金額
* 作廢 / 折讓中的筆數
* 本期已收 / 已付款金額

這區塊讓使用者進頁後先掌握整體財務壓力與異常數量。

#### Tab 切換區

建議採用：

* 發票
* 收款
* 付款

這樣使用者可切換視角，但仍停留在同一個管理模組裡。

#### 篩選區

建議提供：

* 日期區間
* 客戶
* 案件 / 商機 / 專案
* 狀態
* 是否逾期
* 是否異常
* 發票類型 / 收付款類型
* 負責人
* 關鍵字搜尋

#### 主列表區

用表格顯示資料，利於比較與批次掃描。

---

### 6.2 詳情頁結構

詳情頁建議不要做成一長頁直接往下堆，而是做成**頁籤式詳情頁**。建議頁籤如下：

* 基本資訊
* 發票資訊
* 收款 / 付款紀錄
* 對帳 / 關聯資料
* 異動紀錄
* 附件與備註

這樣可把大量資訊分層，不會擠在同一畫面。

## 七、列表頁企劃

## 7.1 發票列表

用途是查看所有發票資料與異動狀態。

建議欄位：

* 發票編號
* 客戶名稱
* 關聯案件 / 商機
* 發票日期
* 發票金額
* 稅額 / 未稅金額
* 發票狀態
* 收款狀態
* 關聯收款金額
* 更新時間

建議狀態至少包含：

* 待開立
* 已開立
* 作廢
* 折讓中
* 已折讓
* 待重開
* 已重開

## 7.2 收款列表

用途是查看應收與實收狀況。

建議欄位：

* 收款編號
* 客戶名稱
* 關聯發票 / 營收
* 應收金額
* 已收金額
* 未收金額
* 收款狀態
* 到期日
* 最後收款日
* 是否逾期
* 更新時間

建議狀態至少包含：

* 待收款
* 部分收款
* 已收款
* 逾期未收
* 收款異常

## 7.3 付款列表

用途是查看應付款與付款進度。

建議欄位：

* 付款編號
* 收款對象 / 供應商 / 分潤對象
* 關聯資料
* 應付款金額
* 已付款金額
* 未付款金額
* 付款狀態
* 到期日
* 最後付款日
* 是否逾期
* 更新時間

建議狀態至少包含：

* 待付款
* 部分付款
* 已付款
* 逾期未付
* 付款異常

## 八、詳情頁企劃

詳情頁應是本模組的主要作業頁，因此不只是展示，還要支援管理。

### 8.1 基本資訊頁籤

顯示：

* 單據編號
* 類型（發票 / 收款 / 付款）
* 客戶 / 對象
* 關聯案件 / 商機 / 專案
* 建立時間
* 更新時間
* 建立人 / 負責人
* 目前整體狀態

### 8.2 發票資訊頁籤

顯示：

* 發票號碼
* 發票類型
* 開立日期
* 金額資訊
* 稅額 / 未稅金額
* 發票狀態
* 作廢 / 折讓 / 重開狀態
* 作廢原因
* 折讓原因
* 重開原因
* 重開後對應新發票

此頁籤也應支援操作：

* 標記作廢
* 標記折讓
* 標記待重開 / 已重開
* 補充異動原因

### 8.3 收款 / 付款紀錄頁籤

顯示：

* 應收 / 應付款總額
* 已收 / 已付款金額
* 未收 / 未付款金額
* 收付款方式
* 銀行帳戶 / 交易資訊
* 分次紀錄清單
* 最後一次處理時間
* 到期日 / 逾期資訊

此頁籤需明確支援：

* 部分收款 / 部分付款
* 新增一筆收付款紀錄
* 更新收付款狀態
* 查看累積進度

### 8.4 對帳 / 關聯資料頁籤

顯示：

* 關聯營收
* 關聯對帳資料
* 關聯訂單 / 報價 / 合約
* 關聯客戶 / 案件
* 差異狀態
* 是否已完成對帳

這能讓這頁不是孤立財務資料，而能接回 CRM 其他模組。

### 8.5 異動紀錄頁籤

顯示：

* 狀態變更紀錄
* 作廢 / 折讓 / 重開紀錄
* 收付款更新紀錄
* 操作人
* 操作時間
* 備註 / 原因

這是很重要但常被漏掉的地方，因為財務資料很需要追溯。

### 8.6 附件與備註頁籤

顯示：

* 發票附件
* 付款證明
* 匯款憑證
* 折讓相關文件
* 備註
* 內部說明

第一版不一定要做很強的文件管理，但至少要能上傳與查看(資料如果是圖片請產生隨機文件圖, 文件則用空檔, 重點是要可以模擬上傳, 上傳以後要可以預覽上傳的資料)。

## 九、重要功能補充

這頁有幾個很重要、不能漏掉的功能：

### 9.1 作廢 / 折讓 / 重開

這不應只是單一按鈕，而是一組完整異動處理能力。
至少要能：

* 標記異動類型
* 記錄原因
* 保留原始紀錄
* 顯示後續狀態
* 連結到新發票或修正資料

### 9.2 部分收款 / 部分付款

這一定要支援，不能只做已收 / 未收兩種狀態。
應能顯示：

* 總額
* 已處理金額
* 剩餘金額
* 各次紀錄

### 9.3 異常提醒

應明確標示：

* 逾期未收
* 逾期未付
* 發票已開但尚未收款
* 折讓後未同步
* 作廢後仍有關聯
* 金額不一致

### 9.4 關聯追溯

每筆資料要能追到：

* 客戶
* 商機 / 案件
* 營收
* 對帳
* 訂單 / 合約 / 報價

### 9.5 備註與原因

財務異動不能只改狀態，必須能留原因與說明。

### 9.6 附件

至少要能附：

* 發票檔
* 收款證明
* 付款憑證
* 折讓 / 作廢相關文件

## 十、是否需要管理功能

需要，而且這頁不是只有查詢，而是要具備基本管理能力。第一版至少應包含：

* 建立發票 / 收付款資料
* 編輯基本資料
* 新增收付款紀錄
* 更新狀態
* 處理作廢 / 折讓 / 重開
* 補備註與原因
* 附件上傳
* 查看歷程

也就是說，這頁應定位為**發票與收付款管理頁**，不只是檢視頁。

## 十一、第一版建議功能範圍

建議納入：

* 摘要卡
* Tab 切換（發票 / 收款 / 付款）
* 篩選區
* 表格列表
* 獨立詳情頁
* 頁籤式詳情資訊
* 作廢 / 折讓 / 重開
* 部分收款 / 部分付款
* 關聯資料查看
* 異動紀錄
* 備註與附件

建議先不納入：

* 複雜審批流程
* 大型批次作業中心
* 進階自動化對帳
* 太重的報表儀表板
* 完整會計帳務系統功能

第一版重點應是：**把單筆財務資料管理完整、看得懂、追得到、改得動。**

## 十二、與其他頁面的分工

這頁與其他模組應這樣分工：

* 營收資料頁：看營收與結算結果
* 對帳管理頁：比對資料一致性與差異
* 分潤管理頁：管理內部分配
* 發票 / 收付款頁：管理單筆發票與金流狀態

也就是說，這頁承接的是更具體、更可操作的財務單據與金流資料。

## 十三、企劃結論

財務與結算的發票 / 收付款頁，應定位為**單筆財務資料的管理模組**。由於資料量大、狀態複雜、異動處理多，因此**必須採用列表頁 + 獨立詳情頁**，而不是只用抽屜承接。

最適合的第一版架構是：

* 上方摘要卡
* 發票 / 收款 / 付款 Tab
* 篩選|表格列表
* 獨立詳情頁
* 詳情頁內用頁籤分區承接大量資訊與操作
