# 報表中心｜分潤分析頁企劃

## 一、頁面定位

分潤分析頁的定位，不是分潤管理頁的延伸，也不是單純把 Settlement / SettlementLine 做成幾張圖，而是 CRM 報表中心中專門用來回答「目前分潤支出規模如何、主要分給誰、是否過度集中、哪類合作模式的分潤負擔較高、分潤趨勢是否異常、哪裡有風險」的管理分析頁。

依照企劃正文，財務 / 分潤模組中已包含 Settlement、SettlementLine、分潤計算、分潤狀態與異常提醒；Analytics 也明確包含分潤分析；Finance Dashboard 更要求分潤摘要、各夥伴分潤、逾期未付款與異常提醒，因此分潤分析頁應該定位為**跨期間、跨夥伴、跨合約、跨產品 / 專案的分潤決策分析頁**，而不是單筆分潤作業頁。

## 二、頁面目的

本頁主要目的如下：

1. 分析整體分潤支出規模、趨勢與變化
2. 查看不同夥伴、客戶、產品、地區、合作模式的分潤結構
3. 分析分潤占營收比與分潤成本壓力
4. 識別高分潤對象、高成長分潤來源與異常支出來源
5. 幫助財務與管理層判斷分潤是否健康、是否過度集中
6. 提供風險控管與合作策略調整的依據

這也符合企劃正文中 Finance 的核心任務：金流正確、風險控管、結算管理；以及管理層看 KPI、看異常、做決策的使用方式。

## 三、適用角色

本頁主要服務以下角色：

* Finance：核心使用者
* Manager / Executive：主要管理使用者
* Admin：查看全域分析
* BD 主管：查看合作結果對應的分潤結果

這也符合原企劃中的角色設定：Finance 需要看分潤摘要、異常提醒與結算狀態；管理層則需要從更高層次理解分潤結構與風險。

## 四、這頁真正要回答的問題

這頁應該幫使用者快速回答以下問題：

* 目前分潤總額是多少？和上期相比是增加還是下降？
* 分潤主要分給哪些夥伴、客戶或對象？
* 哪些產品 / 地區 / 合作模式的分潤支出最高？
* 分潤占營收比是否合理？是否有明顯偏高區塊？
* 分潤是否過度集中在少數對象？
* 哪些來源的分潤支出成長過快？
* 哪些分潤仍待確認、待發放或存在異常？

這些問題都能直接對應到企劃正文中的 Settlement、SettlementLine、RevenueRecord、Contract、Partner / Account、Finance Dashboard 與 Analytics 定義。

## 五、設計判斷

這頁**不應以列表為主體**，因為它是報表分析頁，不是分潤管理頁。
但它也**不能只有圖表**，因為財務或管理者看到異常後，仍需要追到具體分潤對象與明細。

因此最適合的結構仍是：

**上方 KPI 摘要 + 中段主分析圖表 + 下段可下鑽的分潤明細清單**

也就是說，這頁應是「**分析主導、清單輔助**」的頁面。

## 六、主 UIUX 建議

建議這頁採用以下結構：

* 上方：摘要 KPI 區
* 中段：篩選器區 + 主要分析圖表區
* 下段：對應分潤明細清單 / 明細區

這樣最符合報表頁的定位，也能和前面的客戶分析、商機分析、營收分析頁保持一致。

## 七、頁面資訊架構

### 7.1 頂部 KPI 摘要區

這區的目的是讓使用者一進頁就先掌握整體分潤規模與成本壓力。建議放以下 KPI：

#### 1. 分潤總額

用途：查看整體分潤支出規模。
呈現方式：**KPI 卡**

#### 2. 分潤占營收比

用途：查看分潤成本相對營收的壓力。
呈現方式：**KPI 卡**
建議補充：較上期變化

#### 3. 本期新增分潤案件數

用途：查看本期新增需分潤的案件規模。
呈現方式：**KPI 卡**

#### 4. 平均單筆分潤金額

用途：查看單筆 Settlement 的平均成本。
呈現方式：**KPI 卡**

#### 5. 高分潤對象數

用途：查看高支出對象池規模。
呈現方式：**KPI 卡**

#### 6. 高成長分潤來源數

用途：查看分潤支出快速成長的來源數量。
呈現方式：**KPI 卡**

#### 7. 待發放分潤總額

用途：查看目前待付款壓力。
呈現方式：**KPI 卡**

#### 8. 異常 / 爭議分潤案件數

用途：查看存在爭議、延遲或異常的案件規模。
呈現方式：**KPI 卡**

這些指標直接呼應企劃正文中的分潤計算、分潤狀態、分潤明細、分潤摘要、逾期未付款與異常提醒。

### 7.2 篩選區

建議提供：

* 日期區間
* 夥伴 / 客戶
* 合作模式
* 產品 / 遊戲
* 地區
* 合約
* 分潤狀態（draft / reviewing / confirmed / paid）
* 是否待發放
* 是否異常 / 爭議
* 幣別
* 是否高分潤 / 高成長

這些篩選條件可直接對應 Settlement、SettlementLine、Contract、RevenueRecord、Account、Product / Game、Region 等資料模型。

### 7.3 主分析區

主分析區建議分成 4 個分析群組。

---

## A. 分潤趨勢分析

回答「分潤支出有沒有在擴大」。

### 1. 分潤總額趨勢

用途：看每月 / 每季分潤支出變化。
圖形建議：**折線圖**
原因：適合時間趨勢觀察。

### 2. 分潤占營收比趨勢

用途：看分潤成本壓力是否上升。
圖形建議：**折線圖**
原因：比率型指標最適合看趨勢。

### 3. 期間分潤分布

用途：看不同月份 / 季度的分潤高低。
圖形建議：**直條圖**
原因：適合做期間量級比較。

### 4. 已確認 / 已發放 / 待發放分潤趨勢

用途：看分潤狀態隨時間的變化。
圖形建議：**堆疊長條圖**
原因：適合同時看總量與狀態結構。

---

## B. 分潤結構分析

回答「分潤主要分到哪裡」。

### 5. 夥伴分潤分布

用途：看不同夥伴取得的分潤占比。
圖形建議：**橫向長條圖**
原因：名稱可能較長，也適合做排行。

### 6. 產品 / 遊戲分潤分布

用途：看不同產品帶來的分潤支出結構。
圖形建議：**橫向長條圖**

### 7. 地區分潤分布

用途：看不同市場的分潤成本結構。
圖形建議：**橫向長條圖**

### 8. 合作模式分潤分布

用途：看 agency、license、channel、co_branding 等模式的分潤結構。
圖形建議：**Donut 圖** 或 **直條圖**
建議：若要看占比結構用 Donut，若要比較實際數值用直條圖。

### 9. 分潤集中度

用途：看分潤是否過度集中在少數夥伴 / 對象。
圖形建議：**Pareto 圖**
第一版若要簡化，可做 **Top 10 夥伴分潤排行 + 其餘合併**。

---

## C. 分潤價值與貢獻分析

回答「誰拿最多、哪些來源成長最快」。

### 10. Top 夥伴分潤排行

用途：看取得最多分潤的夥伴。
圖形建議：**橫向長條圖**

### 11. Top 合約分潤排行

用途：看哪些合約導致最大分潤支出。
圖形建議：**橫向長條圖**

### 12. Top 產品分潤排行

用途：看哪個產品的分潤成本最高。
圖形建議：**橫向長條圖**

### 13. 高成長分潤來源排行

用途：看哪些夥伴 / 合約 / 產品的分潤支出成長最快。
圖形建議：**橫向長條圖**

### 14. 平均單位分潤趨勢

用途：看平均單筆 Settlement 或平均單對象分潤是否上升。
圖形建議：**折線圖**

### 15. 分潤占營收比排行

用途：看哪些來源雖有營收，但分潤比例偏高。
圖形建議：**橫向長條圖**
原因：這是管理層很需要的「效益判斷」圖。

---

## D. 異常與風險分析

回答「哪些分潤可能有問題」。

### 16. 待發放分潤趨勢

用途：看未付款分潤是否持續累積。
圖形建議：**直條圖**

### 17. 異常 / 爭議案件趨勢

用途：看分潤爭議或異常案件是否增加。
圖形建議：**折線圖** 或 **直條圖**

### 18. 異常原因分布

用途：看分潤爭議、對帳異常、資料缺漏、延遲付款等原因分布。
圖形建議：**橫向長條圖**

### 19. 高風險分潤來源分布

用途：看高風險案件集中在哪些夥伴、產品、地區或合作模式。
圖形建議：**堆疊長條圖**

### 20. 待確認 / 待發放 / 爭議案件結構

用途：看問題案件的狀態組成。
圖形建議：**堆疊長條圖** 或 **Donut 圖**
建議：第一版可用堆疊長條，較便於比較。

---

### 7.4 下段明細區

這區很重要，因為使用者看到圖表異常後，會想知道具體是哪個夥伴、哪份合約、哪筆分潤有問題。

建議放一個可切換的明細表格，預設可切：

* 高分潤對象
* 高成長分潤來源
* 高分潤占比來源
* 待發放分潤
* 異常 / 爭議案件
* 合約明細
* 產品明細

表格欄位建議包含：

* 分潤對象名稱
* 對象類型（夥伴 / 客戶 / 合約 / 產品）
* 地區
* 合作模式
* 分潤總額
* 對應營收
* 分潤占營收比
* 分潤狀態
* 發放狀態
* 最近結算期間
* 異常狀態

## 八、頁面互動邏輯

### 8.1 圖表點擊下鑽

建議圖表可點擊，例如：

* 點某夥伴 → 下方只顯示該夥伴分潤明細
* 點某合作模式 → 下方切出該模式的所有分潤案件
* 點高風險柱狀 → 下方列出高風險案件
* 點 Top 排行中的某合約 → 下方聚焦對應合約分潤明細

### 8.2 KPI 與圖表連動

例如點擊「待發放分潤總額」，中段直接聚焦待發放與風險分析，下段切成待發放分潤清單。
點擊「分潤占營收比」，則聚焦成本結構與高占比來源分析。

### 8.3 延伸跳轉

下方明細表格可依來源類型跳轉：

* 夥伴 / 客戶 → 對應詳情頁
* 合約 → 合約詳情頁
* 產品 / 專案 → 對應詳情頁
* Settlement → 分潤管理頁 / 詳情頁

這樣分析頁與操作頁就能接起來。

## 九、分析維度建議

建議至少支援以下分析維度：

* 時間：月 / 季 / 年
* 夥伴 / 客戶
* 合作模式
* 產品 / 遊戲
* 地區
* 合約
* 分潤狀態
* 發放狀態
* 幣別
* 分潤占營收比區間
* 是否異常 / 爭議

這些維度能和原企劃中的 Settlement、SettlementLine、RevenueRecord、Contract、Account、Product / Game、Region 等模組形成跨模組分析。

## 十、是否需要詳情頁

這頁**本身不需要單獨詳情頁**。
原因是它是報表分析頁，不是作業管理頁。

但它需要兩種延伸查看能力：

1. 下段分潤明細清單
2. 跳轉到分潤管理頁、合約頁或對應來源詳情頁

也就是說，這頁不用為「分潤分析報表本身」做詳情頁，而是應把詳細動作導回既有的資料頁。

## 十一、與其他頁面的分工

這頁和其他頁面應清楚分工：

* 分潤管理頁：主責分潤建立、編修、狀態與發放管理
* 對帳管理頁：主責對帳與差異處理
* 營收資料頁：主責營收來源追查
* 發票 / 收付款頁：主責金流與單據管理
* 分潤分析頁：主責跨來源、跨期間的分潤趨勢、結構、成本壓力與風險判讀

也就是說，分潤分析頁不是為了取代分潤管理頁，而是提供管理與策略視角。

## 十三、第一版建議功能範圍

### 建議納入

* KPI 摘要

### 建議先不納入

* 太複雜的 AI 預測模型
* 過度細緻的自訂報表設計器

第一版應優先做到：**看得懂分潤趨勢、找得到主要分潤對象、抓得到高占比與高風險案件。**

## 十四、頁面結論

報表中心的分潤分析頁，應定位為**管理層與財務的分潤決策分析頁**，而不是分潤管理列表的圖表版。它要承接企劃正文中對分潤計算、分潤明細、分潤狀態、分潤摘要與異常提醒的要求，並用「KPI + 分析圖表 + 可下鑽明細」的方式呈現，讓使用者既能看整體，也能追到具體來源。
