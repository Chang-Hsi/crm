## 一、頁面定位

這頁的目標是讓管理者能完成以下事情：

* 連接外部系統
* 開關某個整合是否啟用
* 設定資料同步方向與頻率
* 設定欄位對應規則
* 設定事件通知/Webhook
* 查看最近同步是否成功，失敗原因是什麼

所以這頁不是「資料編輯頁」，而是**設定與監控頁**。

---

## 二、頁面結構建議

### 1. 頁首區

顯示：

* 頁面標題：系統整合
* 說明文字：管理 CRM 與外部系統的連線、同步與通知設定
* 右上角主操作：

  * `新增整合`
  * `重新同步`
  * `查看同步紀錄`

---

### 2. 摘要卡區

用 4 張簡單資訊卡即可：

* **已啟用整合數**
* **最近 24 小時同步成功次數**
* **最近 24 小時同步失敗次數**
* **最後同步時間**

這區目的是讓管理者一進來就知道目前系統有沒有異常。

---

### 3. 主內容區：Tab 切換

建議用 Element Plus 的 `el-tabs`

Tab 建議有 4 個：

1. **整合服務**
2. **同步規則**
3. **Webhook / 通知**
4. **同步紀錄**

這樣最直覺，也方便日後擴充。

---

## 三、Tab 1：整合服務

這個 Tab 是管理「接了哪些系統」。

### 呈現方式

建議用 **卡片列表** 或 **表格列表** 都可以。
如果系統數量不多，卡片比較好理解；如果會很多，表格比較實用。
我建議第一版用 **表格**，比較符合後台管理感。

### 欄位建議

* 系統名稱
* 類型
* 連線狀態
* 啟用狀態
* 最後同步時間
* 建立時間
* 操作

### 類型範例

* Email
* Calendar
* ERP / 訂單系統
* 客服 / Issue 系統
* 表單工具
* 通知工具
* 自訂 API

### 狀態

* 未連線
* 已連線
* 驗證失敗
* 同步異常

### 操作

* `查看詳情`
* `編輯設定`
* `測試連線`
* `啟用 / 停用`
* `重新驗證`
* `刪除`

### 互動建議

點擊 `查看詳情` 或 `編輯設定` 時，用 **Drawer** 即可，不一定要跳頁。

---

## 四、整合服務 Drawer 規劃

這個 Drawer 是整頁核心。

### Drawer 區塊建議

#### A. 基本資訊

* 系統名稱
* 系統類型
* 描述
* 啟用開關

#### B. 驗證方式

依類型顯示不同欄位，例如：

* API Key
* Client ID
* Client Secret
* Access Token
* Endpoint URL
* Tenant / Workspace ID

密碼類欄位要可隱藏/顯示，但預設遮罩。

#### C. 連線設定

* API Base URL
* Timeout 秒數
* Retry 次數
* 是否啟用自動重試
* IP 白名單提示（純提示即可）

#### D. 測試區

* `測試連線` 按鈕
* 顯示最近一次測試結果
* 顯示錯誤訊息

#### E. 補充說明

若是自訂 API，可提供一個簡單 `說明文字區塊`，提示支援的事件格式。

### Drawer 底部操作

* `取消`
* `儲存`
* `儲存並測試`

---

## 五、Tab 2：同步規則

這個 Tab 管的是「資料怎麼同步」。

建議採用 **上方篩選 + 下方表格**。

### 篩選條件

* 整合系統
* 資料類型
* 同步方向
* 啟用狀態

### 表格欄位

* 規則名稱
* 所屬系統
* 資料類型
* 同步方向
* 同步頻率
* 衝突處理
* 啟用狀態
* 最後執行時間
* 操作

### 資料類型範例

* 客戶
* 聯絡人
* 商機
* 報價
* 訂單
* Issue / 客訴
* 活動紀錄

### 同步方向

* CRM → 外部系統
* 外部系統 → CRM
* 雙向同步

### 同步頻率

* 即時
* 每 5 分鐘
* 每小時
* 每日
* 手動

### 衝突處理

* 以 CRM 為主
* 以外部系統為主
* 以最新更新時間為主
* 發生衝突時建立待確認項目

---

## 六、同步規則 Drawer 規劃

### A. 基本設定

* 規則名稱
* 整合系統
* 資料類型
* 啟用開關

### B. 同步方式

* 同步方向
* 同步頻率
* 是否允許手動觸發
* 是否僅同步符合條件資料

### C. 條件過濾

例如：

* 僅同步已成交商機
* 僅同步指定客戶分群
* 僅同步狀態為 Open 的 Issue

可先用簡單條件列，不需要做太複雜的條件編輯器。

### D. 衝突規則

* 衝突判定方式
* 衝突處理方式
* 是否通知管理者

### E. 欄位對應

這部分建議做成簡單表格：

* CRM 欄位
* 外部欄位
* 是否必填
* 預設值
* 轉換規則

例如：

* 公司名稱 → customer_name
* 聯絡人 Email → contact_email
* 商機金額 → amount

第一版先支援簡單 mapping 就好，不需要做到複雜腳本轉換。

---

## 七、Tab 3：Webhook / 通知

這個 Tab 用來設定「發生事件時要通知誰、推送到哪」。

### 建議分兩塊

#### A. Webhook 設定

表格欄位：

* 名稱
* Endpoint URL
* 觸發事件數
* 簽章驗證
* 啟用狀態
* 最後發送時間
* 操作

#### B. 通知規則

表格欄位：

* 規則名稱
* 事件類型
* 通知管道
* 接收對象
* 啟用狀態
* 操作

### 事件類型範例

* 新 Lead 建立
* 商機成交
* 報價送出
* 客訴建立
* 客訴升級
* 同步失敗
* API 驗證失敗

### 通知管道

* Email
* Slack / Teams
* 系統內通知
* Webhook

### Webhook Drawer 欄位

* 名稱
* Endpoint URL
* Secret
* Request Method
* Header 設定
* 觸發事件多選
* 重送策略
* 啟用開關

### 通知規則 Drawer 欄位

* 規則名稱
* 事件類型多選
* 通知方式多選
* 接收人 / 群組
* 是否合併通知
* 是否僅通知失敗事件

## 八、Tab 4：同步紀錄

這頁很重要，因為整合出了問題通常都要來這裡查。

### 呈現方式

建議：

* 上方篩選
* 下方表格
* 點擊單筆後用 Drawer 看詳情

### 篩選條件

* 系統
* 類型
* 執行結果
* 日期區間
* 關鍵字

### 表格欄位

* 執行時間
* 整合系統
* 規則/事件名稱
* 類型
* 結果
* 處理筆數
* 耗時
* 操作

### 結果狀態

* 成功
* 部分成功
* 失敗
* 重試中

### 詳情 Drawer

* 基本資訊
* Request 摘要
* Response 摘要
* 錯誤訊息
* 重試紀錄
* `重新執行` 按鈕

注意這裡不建議直接完整顯示超長 JSON 在列表中，詳情內再看就好。
若真的要看原始內容，可以用 `Collapse + code block` 顯示。

---

## 九、權限建議

這頁一定要做權限控管。

### 角色建議

* **超級管理員**：可新增、編輯、刪除整合
* **系統管理員**：可編輯與測試連線，但不可刪除關鍵整合
* **一般主管**：可查看同步狀態與紀錄
* **一般使用者**：通常不開放

---

## 十、頁面互動原則

這頁我建議遵守幾個原則：

### 1. 以表格 + Drawer 為主

不用跳太多頁，維持設定流暢性。

### 2. 高風險操作要二次確認

例如：

* 刪除整合
* 停用同步規則
* 重新驗證憑證
* 手動重送大量同步

### 3. 狀態一定要明確

連線中、成功、失敗、部分成功，要有清楚 Tag。

### 4. 錯誤訊息要可追

不能只顯示「失敗」，要能看到失敗原因。

### 5. 不需要富文本

這頁多數是設定資料，**Textarea 就夠了**，不需要 Tiptap。
只有像「Webhook 說明」、「備註」這類欄位才可能用 Textarea。

## 十一、第一版 MVP 建議

如果你想先做能上線的版本，我建議先做這些：

### 必做

* 整合服務列表
* 新增 / 編輯整合 Drawer
* 測試連線
* 同步規則列表
* 欄位對應簡單設定
* 同步紀錄列表
* 單筆紀錄詳情 Drawer

### 可第二階段再做

* Webhook 簽章進階設定
* 條件式同步規則編輯器
* 批次重送
* 視覺化同步流程圖
* 多層通知策略

---

## 十二、你這個專案我會怎麼定義這頁

若跟你目前的 B2B CRM 企劃脈絡接起來，我會把這頁主要服務這幾件事：

* 商機 / 報價 / 客戶資料與 ERP 或訂單系統同步
* 客訴 / Issue 與客服系統或工單系統同步
* Email / Calendar 活動回寫 CRM
* 關鍵事件通知到 Slack / Email
* 管理同步失敗與人工重送

所以它本質上是：**讓 CRM 與外部世界接軌的控制中心**。
