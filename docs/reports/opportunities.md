# 報表中心｜商機分析頁企劃

## 一、頁面定位

商機分析頁的定位，不是商機管理頁的延伸，也不是把商機列表做成幾張圖，而是 CRM 報表中心中專門用來回答「目前商機池健康嗎、哪些階段卡住、轉換率好不好、未來成交是否穩定、團隊推進效率如何」的管理分析頁。

依照企劃正文，商機管理本身已包含商機列表、Pipeline、Forecast、報價管理與商機階段歷程；而報表中心又明確包含商機分析，Analytics 也列出商機轉換率、業績達成率、管理層 KPI 檢視，Manager Dashboard 更要求全公司 Pipeline、各階段數量 / 金額與成交預測，因此商機分析頁應該定位為**跨商機、跨 owner、跨時間區間的分析決策頁**，而不是單筆商機操作頁。

## 二、頁面目的

本頁主要目的如下：

1. 分析目前整體商機池的規模與結構
2. 查看各階段 Pipeline 的數量、金額與分布
3. 分析商機轉換率與卡關階段
4. 查看不同 owner / 團隊的商機推進效率
5. 評估未來一段時間的成交預測與風險
6. 幫助管理層判斷資源投入與業績達成可能性

這和企劃正文中的管理層流程一致：先看 KPI、再看報表、發現低轉換或異常，最後做出分配資源與調整策略的決策。

## 三、適用角色

本頁主要服務以下角色：

* Manager / Executive：主要使用者
* Admin：查看全域分析
* BD 主管：查看團隊 Pipeline 與轉換成果
* 一般 BD：可看自己範圍的精簡版分析

這也符合原企劃中的角色導向：BD 有自己的商機 Dashboard 與個人 Pipeline，主管 / 管理層則需要全局商機分析頁。

## 四、這頁真正要回答的問題

這頁應該幫使用者快速回答以下問題：

* 目前全公司有多少商機？總金額是多少？
* 各階段商機分布是否健康？
* 哪些階段停留太久、容易卡住？
* 商機轉換率如何？近期有上升還是下降？
* 哪些 owner / 團隊的推進效率較好？
* 哪些商機雖然金額大，但成交風險高？
* 未來一段時間預計可成交多少金額？
* 達成率是否落後，需要哪裡補強？

這些都能直接從企劃正文中找到基礎：Opportunity 有 stage、probability、expected_revenue、expected_close_date、owner、lost_reason；另有 OpportunityStageHistory；Dashboard 與 Analytics 也要求 Pipeline、Conversion、Forecast、業績達成率與全局商機分析。

## 五、設計判斷

這頁**不應以列表為主體**，因為它是報表分析頁，不是商機管理頁。
但它也**不能只有圖表**，因為主管看到異常後，還是需要知道是哪幾筆商機出了問題。

因此最適合的結構仍是：

**上方 KPI 摘要 + 中段主分析圖表 + 下段可下鑽的商機清單**

也就是說，這頁應是「**分析主導、清單輔助**」的頁面。

## 六、主 UIUX 建議

建議這頁採用以下結構：

* 上方：摘要 KPI 區
* 中段：篩選器區|主要分析圖表區
* 下段：對應商機清單 / 明細區

這樣最符合企劃正文中報表頁的定位，也能和你剛剛完成的客戶分析頁風格保持一致。

## 七、頁面資訊架構

### 7.1 頂部 KPI 摘要區

這區的目的是讓主管一進頁就先掌握商機池健康度與本期業績壓力。建議放以下 KPI：

#### 1. 商機總數

用途：查看目前商機池規模。
呈現方式：**KPI 卡**

#### 2. 商機總金額

用途：查看目前 Pipeline 總額。
呈現方式：**KPI 卡**

#### 3. 本期新增商機數

用途：查看新商機開發量。
呈現方式：**KPI 卡**

#### 4. 本期新增商機金額

用途：查看本期新機會的金額規模。
呈現方式：**KPI 卡**

#### 5. 商機轉換率

用途：查看整體從建立到成交的效率。
呈現方式：**KPI 卡**

#### 6. 平均商機金額

用途：查看平均單筆商機價值。
呈現方式：**KPI 卡**

#### 7. 預計成交金額

用途：查看未來一段時間 Forecast。
呈現方式：**KPI 卡**

#### 8. 高風險商機數

用途：查看目前風險商機池規模。
呈現方式：**KPI 卡**

這些指標對應到企劃正文中的 Pipeline、Forecast、Conversion、業績達成率與管理層 KPI。

### 7.2 篩選區

建議提供：

* 日期區間
* 商機階段
* 商機類型（agency / license / co_branding / channel）
* 產品 / 遊戲
* 地區
* owner / 部門
* 金額區間
* 預計成交日區間
* 是否高風險
* 是否逾期未推進
* 是否即將成交

這些篩選條件可直接對應 Opportunity 與相關模組欄位。

### 7.3 主分析區

主分析區建議分成 4 個分析群組。

---

## A. 商機結構分析

回答「目前商機盤長什麼樣」。

### 1. Pipeline 階段分布（數量）

用途：看 potential / contacted / proposal / negotiation / won / lost 的數量分布。
圖形建議：**漏斗圖** 或 **直條圖**
建議：若要強調流程遞進感，用漏斗；若要比較各階段數量，用直條圖。

### 2. Pipeline 階段分布（金額）

用途：看各階段 Pipeline 金額結構。
圖形建議：**堆疊長條圖** 或 **直條圖**
原因：金額結構比數量更能代表業績健康度。

### 3. 商機類型分布

用途：看 agency / license / co_branding / channel 的組成。
圖形建議：**Donut 圖**
原因：分類數量不多，適合看占比。

### 4. 地區 / 產品商機分布

用途：看商機主要集中在哪些市場或產品。
圖形建議：**橫向長條圖**
原因：地區 / 產品名稱通常較長，橫條較好讀。

---

## B. 商機價值與 Forecast 分析

回答「商機池值多少、未來會進多少」。

### 5. 商機金額區間分布

用途：看小型、中型、大型商機結構。
圖形建議：**直條圖**
原因：適合區間數量比較。

### 6. Top 商機排行

用途：看目前最值得關注的高金額商機。
圖形建議：**橫向長條圖**
原因：排行型資料最適合。

### 7. 預計成交金額趨勢

用途：看未來每月 / 每季 Forecast 走勢。
圖形建議：**折線圖**
原因：適合看時間趨勢。

### 8. 商機金額集中度

用途：看 Pipeline 是否過度依賴少數大型案件。
圖形建議：**Pareto 圖**
第一版若簡化，可用 **Top 10 長條圖 + 其餘合併**。

---

## C. 轉換與推進效率分析

回答「商機推得動嗎」。

### 9. 商機轉換率趨勢

用途：看整體 Conversion 近期變化。
圖形建議：**折線圖**

### 10. 各階段轉換率

用途：看從 potential → contacted → proposal → negotiation → won 的轉換效率。
圖形建議：**漏斗圖** 或 **分段轉換長條圖**
原因：非常適合看哪個階段流失最多。

### 11. 各階段平均停留天數

用途：看哪個階段卡最久。
圖形建議：**橫向長條圖**
原因：排行和比較清楚。

### 12. 不同 owner 的轉換率比較

用途：看不同業務 / 團隊的推進效率。
圖形建議：**群組長條圖**

### 13. 不同 owner 的 Pipeline 金額比較

用途：看各業務目前手上 Pipeline 規模。
圖形建議：**群組長條圖** 或 **橫向長條圖**

---

## D. 風險與流失分析

回答「哪些商機可能掉單」。

### 14. Lost 商機趨勢

用途：看每月 / 每季 lost 數量或金額變化。
圖形建議：**直條圖**

### 15. Lost 原因分布

用途：看價格、競品、時程、需求不符等失敗原因。
圖形建議：**橫向長條圖**
原因：原因名稱通常較長。

### 16. 高風險商機來源分布

用途：看高風險商機集中在哪些 owner、地區、產品或類型。
圖形建議：**堆疊長條圖**

### 17. 逾期未推進商機數

用途：看哪些案件長時間沒更新。
呈現方式：**KPI 卡** 或小型趨勢卡

### 18. 高風險徵兆分布

用途：看長期未互動、預計成交日延後、長期停在 proposal / negotiation 等風險訊號。
圖形建議：**水平長條圖**

---

### 7.4 下段明細區

這區很重要，因為主管看到某個圖表異常後，會想知道是哪幾筆商機。

建議放一個可切換的明細表格，預設可切：

* 高金額商機
* 即將成交商機
* 逾期未推進商機
* 高風險商機
* Lost 商機
* 高潛力商機

表格欄位建議包含：

* 商機名稱
* 客戶名稱
* 商機類型
* 產品 / 遊戲
* 地區
* owner
* 當前階段
* 預估金額
* 成交機率
* 預計成交日
* 最近更新時間
* 風險狀態
* Lost 原因（若適用）

## 八、頁面互動邏輯

### 8.1 圖表點擊下鑽

建議圖表可點擊，例如：

* 點某階段 → 下方只顯示該階段商機
* 點某 owner → 下方只顯示該 owner 商機
* 點某 Lost 原因 → 下方切出對應 lost 商機
* 點高風險柱狀 → 下方列出高風險商機

### 8.2 KPI 與圖表連動

例如點擊「高風險商機數」，中段直接聚焦風險分析，下段切換成高風險商機清單。
點擊「預計成交金額」，則聚焦 Forecast 分析與即將成交商機。

### 8.3 商機跳轉

下方明細表格應可直接跳到商機詳情頁，因為原企劃中的商機詳情頁本來就承接基本資料、階段歷程、互動紀錄、報價、Forecast 與 Timeline。這樣分析頁與操作頁才能接起來。

## 九、分析維度建議

建議至少支援以下分析維度：

* 時間：月 / 季 / 年
* 商機階段
* 商機類型
* 產品 / 遊戲
* 地區
* owner / 部門
* 金額區間
* 預計成交區間
* 是否高風險
* 是否 lost

這些維度能和原企劃中的 Opportunity、OpportunityStageHistory、Quote、Account、Product / Game 等模組形成跨模組分析。

## 十、是否需要詳情頁

這頁**本身不需要單獨詳情頁**。
原因是它是報表分析頁，不是主檔管理頁。

但它需要兩種延伸查看能力：

1. 下段商機名單
2. 跳轉到商機詳情頁

也就是說，這頁不用為「商機分析報表本身」做詳情頁，而是應把詳細動作導回既有的商機詳情頁。

## 十一、與其他頁面的分工

這頁和其他頁面應清楚分工：

* 商機管理頁：主責商機維護與查詢
* Pipeline 頁：主責商機推進視圖
* Forecast 頁：主責預測與成交規劃
* 商機詳情頁：主責單一商機的全貌與操作
* 商機分析頁：主責跨商機分析、轉換效率、結構與風險辨識

也就是說，商機分析頁不是為了取代 Pipeline，而是提供更高層的管理視角。

## 十三、第一版建議功能範圍

### 建議納入

* KPI 摘要
* 日期 / 階段 / 類型 / owner 等篩選
* 商機結構分析
* 商機價值與 Forecast 分析
* 轉換與推進效率分析
* 風險 / Lost 分析
* 下鑽商機清單
* 跳轉商機詳情頁

### 建議先不納入

* 太複雜的 AI 成交預測模型
* 過度細緻的自訂報表設計器
* 報表內直接編輯商機資料
* 太多進階切換模式

第一版應優先做到：**看得懂 Pipeline 健康度、找得到高潛力商機、抓得到高風險與卡關商機。**

## 十四、頁面結論

報表中心的商機分析頁，應定位為**管理層與業務主管的商機決策分析頁**，而不是商機列表的圖表版。它要承接企劃正文中對 Pipeline、Forecast、商機轉換率、業績達成率與管理層 KPI 的要求，並用「KPI + 分析圖表 + 可下鑽名單」的方式呈現，讓使用者既能看整體，也能追到具體商機。

下一頁最順的通常會接「營收分析頁企劃」，因為這樣報表中心就會從客戶、商機一路接到財務結果。
