# 專案與活動｜任務追蹤企劃

## 一、功能定位

任務追蹤用於管理專案與活動執行過程中的具體工作事項，作為專案管理從「專案層」往下延伸到「執行層」的核心功能。此功能屬於專案與活動模組中的獨立主功能頁，主要負責追蹤每一項任務的狀態、負責人、截止時間、優先級、進度、討論內容與關聯脈絡。

第一版除傳統列表管理外，需同步提供以下視圖與能力：

* 列表視圖
* 看板視圖
* 個人待辦視圖
* 日曆視圖
* 任務留言 / 討論
* 子任務
* 任務模板
* 自動提醒與 SLA 規則畫面
* 任務與里程碑進度自動連動的展示邏輯

其中涉及後端排程、通知發送、歷程紀錄、自動計算、多人同步的部分，第一版可先以前端 mock data、畫面狀態與互動效果實作，先建立完整產品骨架。

---

## 二、第一版產品策略

第一版的實作原則如下：

### 1. 優先完成完整體驗骨架

先把使用者會接觸到的主畫面、切換入口、操作流程、狀態展示與互動形式做完整，讓整體模組可被真實操作與驗證。

### 2. 後端依賴功能先做前端示意

以下能力第一版可先以前端假資料與互動效果完成：

* 自動提醒
* SLA 規則
* 任務到期判斷
* 任務與里程碑進度自動連動
* 留言討論串
* 模板套用
* 子任務彙總
* 視圖切換後的資料同步效果

### 3. 保留未來可接 API 的結構

資料欄位、元件拆分、狀態設計與互動行為要以未來正式串接後端為前提，不做一次性 demo 寫法。

---

## 三、功能目標

任務追蹤模組應支援以下目標：

* 將專案與活動拆解為可管理的任務單位
* 支援任務建立、分派、更新與追蹤
* 提供多視角查看任務的能力
* 支援任務討論、子任務拆解與模板套用
* 協助主管掌握團隊執行負載與風險
* 作為專案進度、里程碑進度與執行層工作的銜接核心

* 任務追蹤主頁

  * 列表視圖
  * 看板視圖
  * 個人待辦視圖
  * 日曆視圖

* 專案詳情頁
* 活動詳情頁
* 里程碑區塊

# 六、任務追蹤主頁企劃

## 6.1 頁面定位

任務追蹤主頁是任務管理的主入口，應整合多種視圖，讓不同角色依據使用情境切換查看方式。主頁需支援跨專案、跨活動、跨人員的任務盤點與執行追蹤。

## 6.2 頁面目標

* 提供多視角查看任務
* 快速辨識待處理、進行中、即將到期與延遲任務
* 支援不同工作習慣的使用者
* 作為新增任務、查看詳情、批次操作的入口

## 6.3 頁面整體結構

### A. 頁首區

內容建議：

* 頁面標題：任務追蹤
* 頁面說明：集中管理專案與活動中的任務、進度、截止時間、討論與執行狀態
* 主要操作：

  * 新增任務
  * 套用模板建立
  * 匯出
  * 批次更新狀態

### B. KPI 摘要區

建議顯示：

* 任務總數
* 待處理任務數
* 進行中任務數
* 今日到期任務數
* 已延遲任務數
* 本週完成任務數

### C. 視圖切換區

提供以下切換：

* 列表
* 看板
* 我的待辦
* 日曆

### D. 全域篩選區

建議支援：

* 關鍵字搜尋
* 任務狀態
* 任務類型
* 優先級
* 負責人
* 協作人
* 關聯專案
* 關聯活動
* 關聯里程碑
* 截止日期區間
* 是否延遲
* 是否我負責
* 是否含子任務
* 是否有未讀留言

# 九、個人待辦視圖企劃

## 9.1 定位

個人待辦視圖用於讓使用者專注查看「自己負責」與「自己需要跟進」的任務，降低資訊干擾，提升日常工作效率。

## 9.2 顯示邏輯建議

預設顯示：

* 我負責的任務
* 我被指派協作的任務
* 我被 @ 提及的任務（第一版可先做假資料顯示）
* 我未完成的高優先級任務
* 今日到期與逾期任務

## 9.3 區塊規劃

建議拆成以下區塊：

* 今天要處理
* 即將到期
* 進行中
* 等待確認
* 已延遲

也可加一個「最近有新留言」區塊。

## 9.4 第一版互動建議

* 支援快速勾選完成
* 快速延後日期
* 快速變更狀態
* 快速回覆留言入口

這些可先做前端互動，不一定需要真的送出後端。

# 十一、任務留言 / 討論企劃

## 11.1 功能定位

任務留言 / 討論用於承載與任務相關的溝通紀錄，避免任務資訊散落在外部聊天工具。它應作為任務詳情頁的重要區塊。

## 11.2 第一版內容規劃

每筆留言建議顯示：

* 留言者
* 留言時間
* 文字內容
* 附件
* 是否為系統紀錄或人工留言

## 11.3 第一版互動建議

* 可新增留言
* 可顯示假 @ 提及效果
* 可顯示留言數
* 可顯示最新留言預覽
* 可切換系統紀錄 / 人工留言

若無後端，留言可先存在前端 mock state 中。

# 十二、子任務企劃

## 12.1 功能定位

子任務用於拆解較大的任務，讓一個任務下可再分成多個更小的執行項目。這對專案型與活動型工作很重要。

## 12.2 顯示方式建議

在任務詳情頁中顯示：

* 子任務清單
* 每筆子任務狀態
* 子任務負責人
* 子任務截止日
* 子任務完成勾選

在列表與看板中則以摘要呈現：

* 3 / 5 已完成

## 12.3 第一版互動建議

* 可新增 / 編輯 / 完成子任務
* 可在詳情頁展開與收合
* 父任務進度可由子任務完成比例自動帶出展示效果

若尚未接後端，自動連動先用前端計算。

# 十四、自動提醒與 SLA 規則企劃

## 14.1 功能定位

自動提醒與 SLA 規則用於定義任務在特定時間點或狀態下，應被標示、提醒或升級處理的規則。

## 14.2 第一版定位

第一版可先做成：

* 規則設定畫面
* 規則摘要顯示
* 任務上對應的提醒狀態與 SLA tag 顯示
* 視覺上的提醒效果

不一定真的發出通知，但要先把規則配置與展示邏輯做出來。

## 14.3 規則示例

* 截止前 3 天提醒
* 截止前 1 天高亮
* 到期未完成標示逾時
* 高優先級任務逾期後標示紅色
* 待確認超過 2 天標示異常

## 14.4 顯示建議

在任務卡片 / 列表中顯示：

* SLA 正常
* 即將逾時
* 已逾時
* 需關注

---

# 十五、任務與里程碑進度自動連動企劃

## 15.1 功能定位

此功能用於建立任務進度與里程碑進度之間的關聯，讓里程碑不是手動孤立更新，而能反映底下任務的完成情況。

## 15.2 第一版設計方式

第一版可先做前端展示邏輯：

* 任務若關聯某里程碑，則里程碑進度根據任務完成比例自動計算
* 專案詳情頁與任務詳情頁都能看到這種連動結果
* 若使用者手動改任務狀態，里程碑完成百分比同步更新畫面

## 15.3 顯示建議

在里程碑區塊顯示：

* 關聯任務數
* 已完成任務數
* 里程碑進度百分比
* 是否已完成

在任務詳情頁顯示：

* 此任務影響哪個里程碑
* 任務完成後對里程碑的貢獻

# 二十一、實作原則建議

第一版可接受以下做法：

* 留言資料使用 mock 陣列
* 子任務完成率以前端 computed 計算
* SLA 狀態以前端日期邏輯計算
* 模板套用以前端預設 JSON 複製生成
* 日曆拖曳改期先只更新前端畫面
* 看板拖曳換欄先只更新本地狀態
* 任務完成與里程碑進度連動先只做畫面層同步

這樣可以先把體驗做完整，之後再分階段接 API。

# 二十二、頁面成功標準

此功能第一版完成後，應達成以下效果：

* 使用者可用多種視角管理任務
* 任務、子任務、留言、到期與提醒資訊集中可見
* 專案與活動的執行工作能真正被拆解與追蹤
* 看板、個人待辦與日曆視圖可滿足不同工作習慣
* 雖然部分功能尚未串後端，但整體操作路徑、畫面結構與互動體驗已接近正式產品
* 後續可平滑擴充成完整的任務管理系統
