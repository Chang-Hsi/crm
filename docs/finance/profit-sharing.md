# 財務與結算｜分潤管理頁企劃

## 一、頁面定位

分潤管理頁的定位，是財務與結算模組中的 **分潤作業管理中心**。它不是單純查看分潤結果的頁面，而是用來管理每筆營收、案件、訂單或合作項目的分潤對象、分潤規則、分潤金額、分潤狀態與發放進度。

這頁的核心價值，在於協助使用者清楚回答以下問題：

* 這筆收入要分給誰
* 每個人應分多少
* 分潤是如何計算的
* 目前分潤是否已確認、已結算、已發放
* 哪些分潤資料仍待處理或有異常

因此，這頁本質上不是報表頁，也不是純明細頁，而是 **具備建立、編輯、確認、追蹤能力的作業管理頁**。

## 二、頁面目的

本頁主要目的如下：

1. 管理各筆案件或營收的分潤資料
2. 設定或調整分潤對象與分潤金額
3. 管理分潤狀態與發放進度
4. 提供分潤來源追溯能力
5. 協助財務、主管或營運人員掌握待結算與待發放的分潤資料
6. 降低人工計算與分潤追蹤成本

## 三、適用角色

本頁主要服務以下角色：

* 財務人員：處理分潤結算與發放
* 業務主管：確認案件分潤合理性
* 營運 / 管理者：查看整體分潤進度與異常
* 部分業務或管理角色：查看自己案件的分潤安排與狀態

## 四、頁面核心概念

分潤管理頁應以「**一筆來源資料，可對應多筆分潤明細**」為核心。

也就是說，一筆分潤資料通常會包含：

* 一個分潤來源
  例如某筆營收、某張訂單、某個商機成交案、某份合約

* 多個分潤對象
  例如業務、主管、代理商、介紹人、合作夥伴

* 多筆分潤明細
  例如 A 分 20%、B 分 10%、C 固定 5000 元

* 一個整體狀態
  例如草稿、待確認、待結算、已結算、已發放

因此這頁不是只管理單個欄位，而是管理一組分潤結果。

## 五、頁面目的導出的 UIUX 判斷

因為這頁要同時支援：

* 查詢全部分潤資料
* 新增 / 編輯單筆分潤
* 管理多個分潤對象
* 更新狀態
* 追蹤發放進度

所以最適合的頁面型態是：

**上方摘要卡 + 篩選|分潤管理列表 + 詳情 / 編輯抽屜**

也就是說，主體仍然應以列表頁為核心，因為使用者需要批次查看與管理多筆資料；但又一定要有可編輯的單筆操作介面，因此需要搭配詳情 / 編輯抽屜。

## 六、是否需要詳情頁

結論：**需要詳情能力，也需要可編輯能力。**

因為列表只能顯示分潤摘要，但無法完整承載：

* 分潤來源資訊
* 分潤規則
* 分潤名單
* 比例與金額
* 狀態與發放紀錄
* 備註與異常原因

因此不能只有列表，一定要能進一步查看與修改。

## 七、詳情頁是否要獨立一頁

結論：**第一版不一定需要獨立詳情頁，建議先使用 Drawer 作為查看與編輯介面。**

原因如下：

* 使用者主要仍在列表中批次處理多筆分潤
* 若每次都跳整頁，管理節奏會被打斷
* 第一版通常還不需要非常複雜的審批與附件流程
* 抽屜很適合承載查看、編輯、狀態更新這類中度操作

但要注意，這裡的 Drawer 不是單純只讀詳情，而是要能支援 **查看 + 編輯 + 狀態操作**。

若未來分潤流程變複雜，例如加入：

* 多階段審批
* 分潤試算版本
* 發放憑證附件
* 歷史版本追蹤
* 批次發放對帳

那再升級成獨立詳情頁會比較合理。

## 八、頁面資訊架構

本頁建議分為四個區塊：

### 8.1 頂部摘要區

用來快速掌握目前整體分潤情況，建議顯示：

* 待確認分潤筆數
* 待結算分潤筆數
* 待發放金額
* 已發放金額
* 異常筆數
* 本期分潤總額

此區塊應簡潔，重點是讓使用者快速掌握工作量與進度。

### 8.2 篩選區

分潤資料通常會跨很多客戶、案件與人員，因此篩選很重要。建議提供：

* 日期區間
* 客戶
* 案件 / 商機 / 專案
* 分潤來源類型
* 分潤對象
* 分潤狀態
* 發放狀態
* 關鍵字搜尋
* 是否只看待處理 / 異常

### 8.3 分潤管理列表

本頁主工作區，負責查看與管理全部分潤資料。

### 8.4 詳情 / 編輯抽屜

點擊單筆資料後，在右側打開 Drawer，顯示完整分潤資訊與可編輯內容。

## 九、分潤管理列表企劃

### 9.1 列表定位

列表不只是查詢結果，而是使用者進行分潤管理的主要入口。使用者應能在這裡快速完成：

* 找到待處理資料
* 查看分潤摘要
* 判斷狀態
* 開啟編輯
* 執行狀態更新

### 9.2 建議欄位

主列表建議顯示以下欄位：

* 分潤編號
* 客戶名稱
* 關聯案件 / 商機 / 專案
* 分潤來源
* 可分潤金額
* 分潤總額
* 分潤對象數
* 分潤狀態
* 發放狀態
* 建立時間 / 更新時間
* 操作

### 9.3 列表互動建議

建議支援以下互動：

* 依日期排序
* 依金額排序
* 依狀態篩選
* 點列開啟詳情 / 編輯抽屜
* 快速切換狀態
* 可標示異常資料

若未來資料量大，也可考慮加入批次操作，但第一版不一定要先做。

## 十、詳情 / 編輯抽屜企劃

### 10.1 抽屜定位

抽屜不是只有看資料，而是承接單筆分潤的主要管理操作。
也就是它要同時具備：

* 查看明細
* 編輯分潤名單
* 調整比例 / 金額
* 更新狀態
* 補充備註

### 10.2 抽屜內容建議

可分成幾個區塊：

#### 基本資訊

* 分潤編號
* 客戶名稱
* 關聯案件 / 商機 / 專案
* 分潤來源
* 建立時間
* 更新時間
* 建立人 / 負責人

#### 金額資訊

* 原始營收 / 來源金額
* 可分潤金額
* 已分配總額
* 剩餘未分配金額
* 是否超額分配

#### 分潤明細

這是最核心區塊，應能管理多筆分潤對象資料，每筆至少包含：

* 分潤對象
* 角色
* 分潤方式（比例 / 固定金額）
* 分潤比例
* 分潤金額
* 備註

這裡應支援：

* 新增一筆分潤對象
* 編輯既有分潤明細
* 刪除分潤明細

#### 狀態資訊

* 分潤狀態
* 發放狀態
* 預計發放日
* 實際發放日
* 異常原因 / 備註

#### 關聯資料

* 關聯營收
* 關聯訂單 / 報價 / 合約
* 關聯客戶 / 案件

## 十一、管理功能範圍

既然這頁是「分潤管理」，那第一版至少要具備以下管理功能：

### 11.1 分潤資料建立

可由使用者手動建立一筆分潤資料，指定來源案件與基本資訊。

### 11.2 分潤明細管理

可新增、編輯、刪除分潤對象與明細。

### 11.3 分潤金額管理

可設定分潤比例或固定金額，並自動計算對應數值。
當用戶設定時，即時響應式的顯示「水平堆疊比例條」, 這個分潤比例預覽條顯示每個人目前分到的比例, 同時顯示 已分配 xx% / 剩餘 xx%, 若超過 100%，直接用異常狀態提示, 也就是說，它不是報表圖，而是 輸入時的檢查輔助元件。

### 11.4 分潤狀態管理

可更新單筆分潤目前處於哪個階段。

### 11.5 發放狀態管理

可標記是否已發放，並記錄日期。

### 11.6 備註與異常管理

可對特例案件填寫說明，例如人工調整原因、暫停發放原因等。

## 十二、狀態設計建議

第一版建議至少定義以下狀態：

### 分潤狀態

* 草稿
* 待確認
* 待結算
* 已結算
* 已作廢

### 發放狀態

* 未發放
* 待發放
* 已發放
* 發放異常

這樣已足夠支撐大部分第一版流程，不宜一開始設計過多狀態。

## 十三、操作原則

本頁應以「**管理與追蹤並重**」為原則，不可只偏向查詢。

因此整體操作應滿足：

* 在列表中快速找到資料
* 在抽屜中完成單筆管理
* 不需頻繁跳頁
* 重要欄位能快速編修
* 狀態變化清楚可追蹤

但第一版仍不建議做得過重，例如先不要放入：

* 分潤規則引擎
* 多版本試算
* 複雜審批流程
* 高度自動化批次發放

## 十四、第一版建議功能範圍

### 建議納入

* 摘要卡
* 篩選區
* 分潤列表
* 新增分潤資料
* 編輯分潤明細
* 新增 / 刪除分潤對象
* 比例 / 金額計算
* 分潤狀態更新
* 發放狀態更新
* 備註欄位
* 抽屜式詳情 / 編輯

### 建議先不納入

* 獨立詳情頁
* 規則模板中心
* 批次大量結算
* 複雜審批流
* 發放對帳整合
* 歷史版本比較

第一版的核心應是：**先把分潤資料管得起來、改得動、追得到。**

## 十五、與其他頁面的分工

本頁應與其他模組清楚分工：

* 營收資料頁：查看營收與結算結果
* 對帳管理頁：核對資料一致性與差異
* 分潤管理頁：管理分潤對象、金額、狀態與發放

也就是說，分潤管理頁承接的是營收結果之後的「內部分配作業」。

## 十六、企劃結論

財務與結算的分潤管理頁，應定位為 **分潤作業與狀態管理頁**。它不能只有查詢功能，而必須具備基本管理能力，包括：

* 建立分潤資料
* 管理分潤對象
* 調整分潤比例 / 金額
* 更新分潤狀態
* 追蹤發放狀態

在 UI 上，第一版最適合採用：

* 上方摘要卡
* 篩選區|分潤列表
* 右側詳情 / 編輯抽屜
