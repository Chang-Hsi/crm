# Dashboard「總覽」頁企劃

## 一、頁面定位

本頁為 CRM 使用者登入後的首頁總覽頁，主要目的是讓使用者在最短時間內掌握目前營運狀態、待處理事項、商機健康度與風險提醒，並快速進入後續工作。依據專案企劃，Dashboard 應作為工作起點，Sidebar 是工具箱，詳情頁才是完成任務的主操作區，因此總覽頁不應承擔過深的資料編輯責任，而應聚焦在「摘要、提醒、導流、決策支援」。

本頁會參考 `crms.dreamstechnologies.com` 的卡片式 Dashboard 風格，採用：

* 上方 KPI 卡片
* 中段主視覺分析區
* 右側提醒 / 待辦區
* 下方多個業務摘要模組

但內容不直接沿用通用 CRM demo，而是改成符合本專案的資料主幹：Account、Opportunity、Quote、Contract、Project、RevenueRecord、Settlement、Issue、Activity / Timeline。這些都是企劃中已明確定義的核心實體。

---

## 二、設計目標

總覽頁要解決的不是「資料很多不知道怎麼塞」，而是以下四件事：

1. 讓使用者一進系統就知道現在狀況怎麼樣
2. 讓使用者立刻看到需要處理的事
3. 讓使用者快速跳到下一步工作
4. 讓主管能快速掌握營運健康度與風險

因此總覽頁應同時具備：

* KPI 摘要
* 任務提醒
* 商機與營收概況
* 近期動態
* 風險預警
* 快速導流入口

這也符合企劃中對不同角色 Dashboard 的定義：BD 看待辦與 Pipeline，Finance 看合約與對帳，Manager 看 KPI、成長率、轉換率與風險。

---

## 三、整體版型規劃

版型可參考推薦網站的節奏，但請改為更符合營運後台的資訊排序。

### 頁面結構

1. 頁首區
2. KPI 摘要卡
3. 主分析區 + 待辦 / 風險側欄
4. 下半部業務摘要模組區
5. 最近活動 / Timeline 區

### 視覺風格

* 使用卡片式區塊
* 以乾淨留白、淺底、輕邊框為主
* 不需要過度裝飾
* 每張卡片都應有明確標題與行動入口
* 主要強調「可讀性」與「掃描速度」

---

## 四、頁首區規劃

頁首區放在最上方，保持簡潔。

### 內容建議

* 頁面標題：`總覽`
* 補充說明：`快速查看目前營運狀態、待處理事項與重要風險`
* 右側操作：

  * 時間範圍切換（本週 / 本月 / 本季）
  * 資料範圍切換（我的 / 部門 / 全部，依權限）
  * `重新整理`
  * `前往報表中心`

### 設計原則

不要放太多操作，這頁不是編輯頁。主要用途是切換視角與刷新資料。

---

## 五、第一區：KPI 摘要卡

這區參考推薦網站最上方 4 張統計卡的節奏，但內容改為你這個 CRM 真正重要的指標。

### 建議第一版顯示 6 張卡

1. 本月營收
2. 本月新增商機金額
3. 進行中商機數
4. 本月成交金額
5. 活躍客戶數
6. 高風險案件數

### 每張卡片內容

* 指標名稱
* 主數值
* 與上期比較（%）
* 小型趨勢提示
* 點擊後導向對應模組

### 對應模組

* 本月營收 → 營收概況
* 商機金額 / 商機數 → 商機概況
* 活躍客戶數 → 客戶列表
* 高風險案件數 → 風險預警

### 規劃原因

企劃中的核心主流程是「客戶 → 商機 → 報價 → 合約 → 專案 → 營收 → 分潤 → 報表」，所以總覽卡片不應只是 generic CRM 的 Leads / CLV / Conversion / Revenue，而應反映這條主流程的重要節點。

## 六、第二區：主分析區

這區是總覽頁中最大的主視覺區塊，建議採 **左大右小**。

### 左側主圖：商機 Pipeline 摘要

這塊是總覽頁最核心的主圖，不建議第一版用營收折線圖當主圖，因為你目前專案 MVP v1 的核心仍是 BD 流程，也就是客戶、商機、互動、Pipeline 推進。

#### 內容建議

* 各階段商機數量
* 各階段商機金額
* 成交率 / 失敗率
* 即將 close 商機數
* 本月預估成交金額

#### 呈現方式

可用：

* 漏斗圖
* 分段柱狀圖
* 分段卡片 + 橫向進度條

第一版若不想裝太多圖表套件，也可先用卡片列 + 金額摘要。

### 右側側欄：待辦與風險

右側不放 calendar，改放更符合你專案的工作提醒。

#### 模組 A：我的待辦

* 今日需跟進客戶
* 即將到期商機
* 待回覆報價
* 未完成任務

這正是 BD Dashboard 企劃裡明確定義的首頁內容。

#### 模組 B：風險提醒

* 長時間未跟進客戶
* 即將到期合約
* 延遲專案
* 高優先 Issue
* 同步異常 / 對帳異常（若已接資料）

這符合企劃中的風險預警與例外流程設計。

---

## 七、第三區：下半部摘要模組

這區可做成 2 x 2 或 3 x 2 的卡片區，延續推薦網站下半部多模組拼接的風格。

### 模組 1：營收摘要

這塊不是完整營收分析，只做摘要。

#### 顯示內容

* 本月 gross revenue
* 本月 net revenue
* 上月對比
* 依地區 / 產品的簡易分布
* `查看更多` 連到營收概況

企劃中明確指出 CRM 會承接營收紀錄、分潤檢視與報表入口，但正式總帳仍由 ERP 主責，所以總覽這裡只做營運級摘要，不做太深的財務細節。

### 模組 2：近期客戶動態

#### 顯示內容

* 最近互動
* 新增客戶
* 近期待回訪客戶
* 最近有異動的重要客戶

這也是 BD Dashboard 企劃中原本就有的內容。

### 模組 3：專案與里程碑摘要

#### 顯示內容

* 進行中專案數
* 延遲專案數
* 本週到期里程碑
* 關鍵專案狀態

因為你的完整藍圖中，專案不是獨立孤島，而是合約後續落地的重要節點，且專案頁會連到任務、風險、營收。

### 模組 4：夥伴績效摘要

#### 顯示內容

* Top 5 夥伴
* 成長最高夥伴
* 異常夥伴數
* 合作模式分布

這對應企劃中的 PRM 與 Manager Dashboard。

---

## 八、第四區：最近活動 / Timeline

這區建議放在頁面最下方，做成可快速瀏覽的動態清單。

### 顯示內容

* 會議紀錄
* Email / 通話
* 商機階段變更
* 報價狀態變更
* 合約更新
* 專案里程碑異動
* Issue / Ticket 更新

企劃已經定義 Timeline 是 UI 聚合視圖，可由 Activity、OpportunityStageHistory、Quote / Contract 變更、Project Milestone、Issue 等事件聚合而成，所以總覽頁很適合放一個精簡版的最近活動模組。

### 設計方式

* 顯示最近 10 筆
* 每筆包含：事件類型、主體名稱、時間、狀態
* 可快速跳轉到詳情頁
* 提供 `查看完整 Timeline`

## 九、角色差異

雖然頁面版型可以共用，但內容要有角色差異。企劃很明確要求角色導向呈現，不同角色不只是權限不同，而是資訊優先順序不同。

### BD / Sales

優先顯示：

* 我的待辦
* 我的 Pipeline
* 我的客戶動態
* 本月成交 / 達成率

### Finance

優先顯示：

* 待對帳
* 待付款 / 收款
* 合約異常
* 分潤待確認
* 本月財務概況

### Manager / Executive

優先顯示：

* 公司 KPI
* 全局 Pipeline
* 營收分布
* 夥伴績效
* 風險與預警

### Admin

採混合總覽型首頁：

* KPI 摘要
* 系統整體營運狀態
* 重要異常提醒
* 各模組入口摘要

這些內容都和企劃中的角色 Dashboard 定義一致。

## 十、第一版 MVP 建議

如果你現在要先開工，我建議總覽頁第一版先做到這裡：

### 必做

* 頁首區
* KPI 卡 6 張
* 我的待辦
* 商機 Pipeline 摘要
* 風險提醒
* 營收摘要
* 最近活動 / Timeline

### 第二階段再補

* 夥伴績效摘要
* 專案與里程碑摘要
* 依角色切換模組
* 更完整的篩選器
* 卡片自訂排序

### 原因

企劃的 MVP v1 核心是「客戶 → 商機 → 互動 → Pipeline 推進」，個人 Dashboard 也在第一版範圍內；但 Quote、Contract、Project、Finance / Settlement 都是後續階段才完整落地，所以首頁也應該跟著 MVP 階段控制深度。

---

## 十一、UI / UX 原則

1. 借用推薦網站的乾淨卡片式結構，但不要直接照抄內容
2. 總覽頁偏「入口頁」而不是「分析頁全集」
3. 讓使用者一眼看懂現況，兩步內進入下一個工作
4. 每張卡片都要有清楚的跳轉目的
5. 少放裝飾型小工具，多放任務型與風險型資訊
6. 不要把 Calendar、Top Country 這種泛用 BI 模組放成首頁主角，除非它和你的核心流程直接相關
