# 商機管理｜合約管理頁 企劃

## 1. 頁面定位

合約管理頁的目標，是把「已成交或進入簽約階段的商機」集中管理，讓業務、主管、法務、財務可以在同一頁掌握：

* 合約建立狀態
* 合約審核進度
* 簽署狀態
* 合約金額與有效期間
* 履約 / 續約 / 到期風險

這一頁不是單純文件列表，而是 **商機成交後的正式承接頁**。
因此它在 CRM 裡應承接：

* 商機詳情頁
* 報價管理頁
* 客戶 / 聯絡人資料
* 簽約與履約追蹤

---

## 2. 頁面目標

合約管理頁需要解決這幾件事：

1. 快速查看目前有哪些商機正在簽約、審核、已生效、即將到期
2. 清楚追蹤每份合約的生命週期
3. 讓使用者可以快速建立新合約、補件、送審、下載、續約
4. 降低合約遺漏、到期未續、審核卡住的風險
5. 與商機資料串接，避免成交後資訊斷層

---

## 3. 頁面使用者

主要使用者：

* 業務：建立合約、查看進度、追蹤簽署
* 業務主管：掌握團隊簽約狀況與卡關案件
* 法務 / 管理者：審核條款、控管版本
* 財務：查看合約金額、付款條件、生效資訊
* 客服 / AM：查看履約中合約與續約時程

---

## 4. 頁面在商機管理中的角色

建議商機管理模組的頁面脈絡可理解成：

* 商機列表：找案件
* Pipeline：看階段分布
* Forecast：看預估業績
* 報價管理：管理報價與版本
* **合約管理：管理成交後的正式合約**
* 商機詳情頁：單一案件完整資訊中心

也就是說，**合約管理頁不是每個商機都會有資料**，原則上應聚焦在：

* 已成交商機
* 已送出報價且準備簽約的商機
* 已建立合約草稿的商機

## 10. 建議支援的操作流程

### 流程 1：新增合約

入口：

* 頁面右上「新增合約」
* 商機詳情頁中的「建立合約」

步驟建議：

1. 選擇關聯商機
2. 自動帶出客戶、聯絡人、報價資訊
3. 填寫合約基本資料
4. 上傳主文件 / 附件
5. 設定生效日、到期日、付款條件
6. 存成草稿或送審

---

### 流程 2：送審合約

適用狀態：草稿 / 退回後修正

動作：

* 點「送審」
* 系統檢查必填欄位與附件
* 成功後狀態切換為「審核中」

---

### 流程 3：簽署追蹤

當審核完成後：

* 狀態進入「待簽署」
* 可記錄：

  * 發送日期
  * 客戶簽署日期
  * 我方簽署日期
  * 預計完成日

也可提供「催簽」功能。

---

### 流程 4：續約

對即將到期或已到期合約：

* 可從原合約快速建立續約版本
* 帶入原客戶、原商機、原條款摘要
* 重新設定期間與金額

---

### 流程 5：作廢 / 終止

適用於：

* 客戶取消
* 商機失敗後合約不成立
* 已簽約但中途終止

需保留：

* 原因
* 操作人
* 操作時間
* 歷程紀錄

---

# 商機管理｜合約詳情頁 企劃

## 1. 頁面定位

合約詳情頁是單一合約的完整資訊中心，用來承接合約管理列表頁的「查看」行為。它的任務不是只有展示欄位，而是要讓使用者在同一頁完成這些事：

* 查看合約基本資訊與商務條件
* 追蹤審核與簽署進度
* 查看版本、附件、變更紀錄
* 快速執行送審、催簽、續約、終止等操作
* 與商機、客戶、報價資料互相串接

因此這頁的角色很像「合約的主檔頁」，和商機詳情頁相同，屬於單一實體的資訊樞紐。

## 2. 頁面目標

這頁完成後，使用者應該能做到：

* 一眼知道這份合約現在處於哪個階段
* 清楚掌握金額、期間、付款條件與關聯商機
* 看出目前卡點是審核、簽署、缺件還是即將到期
* 快速查看附件與版本資訊
* 從這頁直接做後續操作，而不必回列表頁

## 3. 主要使用者

* 業務：追蹤簽約狀態、催簽、補件、續約
* 主管：查看案件風險與進度
* 法務：檢查審核狀態、條款版本、退回原因
* 財務：查看金額與付款條件
* AM / 客服：查看生效中合約與到期資訊

## 4. 頁面進入入口

建議可從以下入口進入：

* 合約管理列表頁點擊合約名稱
* 商機詳情頁中的合約區塊點擊查看
* 客戶詳情頁中的合約清單點擊查看
* 報價管理頁建立後跳轉

## 5. 頁面資訊架構

建議合約詳情頁採用「上方總覽 + 下方分區內容」的模式，避免資訊過度擠在同一區。

整體可分成 6 個主區塊：

1. 頁首總覽區
2. 合約基本資訊區
3. 商務與期間資訊區
4. 審核 / 簽署流程區
5. 文件與版本區
6. 歷程與備註區

若你想讓互動更順，也可以採用 tab 結構，但我更建議第一版先用單頁分區式，因為管理者通常需要快速掃描整體狀況。

## 6. 頁首總覽區

這區是詳情頁最重要的資訊入口，必須一進頁就讓人知道這份合約的狀況。

建議內容：

* 返回按鈕
* 頁面主標題：合約名稱
* 次標資訊：合約編號 / 客戶名稱 / 關聯商機
* 狀態標籤：

  * 合約狀態
  * 簽署狀態
  * 風險標記（缺件 / 逾期 / 即將到期）
* 右側主要操作按鈕：

  * 編輯
  * 送審
  * 下載
  * 催簽
  * 續約
  * 更多

建議總覽卡中再補 4 個快速指標：

* 合約金額
* 生效日
* 到期日
* 距到期天數

這樣使用者不需要往下滑就能先抓到重點。

## 7. 頁面上半部布局建議

左欄 2/3：

* 基本資訊

5. 歷程與備註區
- 使用 ElTimeline 顯示操作歷程
- 顯示建立、編輯、送審、退回、簽署、催簽、終止等紀錄
- 每筆需有：動作名稱、內容、操作人、時間
- 備註區另用 card 顯示

【右側欄位】
1. 狀態摘要卡
- 合約狀態
- 審核狀態
- 簽署狀態
- 距到期天數

2. 風險提醒卡
- 缺件
- 簽署逾期
- 審核退回
- 30 天內到期

3. 關聯資訊卡
- 客戶
- 關聯商機
- 負責業務
- 最近報價單（先用 mock 顯示）

4. 快捷操作卡
- 編輯
- 送審
- 催簽
- 建立續約
- 下載主檔

【狀態規則】
請沿用合約管理頁的狀態：
contractStatus:
- draft
- pending_review
- under_review
- pending_signature
- active
- in_execution
- expiring_soon
- renewed
- completed
- terminated
- voided

signatureStatus:
- not_sent
- signing
- customer_signed
- internal_signed
- fully_signed

另外新增：
reviewStatus:
- not_submitted
- pending
- approved
- rejected

請做對應的狀態文字 mapping 與 Tag 樣式 mapping。

【風險提示邏輯】
請實作：
- 距到期 <= 30 天：高風險
- 距到期 31~60 天：中風險
- 缺附件：顯示缺件
- 已送簽但超過一定天數未完成：顯示逾期簽署
- reviewStatus = rejected：顯示審核退回
